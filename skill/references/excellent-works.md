### 互联网+ 共性结论（只从上面 8 个"看到内容"的条目提炼）

视觉共性：
1. 每页文字极少：评委每页只看 10–15 秒，≤30 字/页是硬约束，数据必须用图表（slide-skill 包明文要求）。
2. 技术页用架构图/流程图，不堆代码、不堆文字（slide-skill 包）。
3. 项目名本身就是视觉钩子："首创/首家/首套/领航者/开拓者"式定位词 + 一个核心技术词，封面只放项目名 + 一句话价值主张。
4. 封面/章节页可以浓，内容页必须让位于数据表和对比图（哪吒、科技小院的新闻转述结构一致）。

逻辑共性：
1. 十指标链是标准骨架：封面 → 政策背景 → 行业现状 → 痛点 → 市场规模 → 项目初心 → 企业信息 → 竞品分析 → 成长记录 → 资源优势（B站金奖案例系列分集结构）。
2. 竞品分析是"最重要的指标之一"，必须单列一页/一集，用一张表讲清 1–2 个差异点。
3. 开场讲痛点，不讲背景：痛点越清晰项目越有价值，配一个真实场景 + 一个有来源的数据。
4. 验证链要写进时间线：成长记录、晋级经历（校赛→省赛→国赛）、第三方奖项，都是"已经做出来"的证据，不是计划。
5. 结尾收在社会价值 + 融资诉求：社会价值必须对应可核查的奖项或数字（带动就业、增产百分比），不要空话。

### 挑战杯共性结论（只从上面 7 个"看到内容"的条目提炼）

视觉共性：
1. 官方格式就是视觉上限：不追求过度视觉化，不用复杂动效、3D、特效字体；封面只有项目名 + 赛道 + 汇报人（青创北京 DOCX 明文）。
2. 数据优先：data-forward 主题，图表、对比表代替文字；文献综述用对比表格，不要逐条罗列（slide-skill 包）。
3. PPT 本身是加分项：图片 + PPT 式视频播放能让评委眼睛不离 PPT；但页码、字体统一这类细节缺了会直接淘汰（知乎经验帖）。

逻辑共性：
1. 学术严谨第一：数据必须有来源，创新点必须量化（"与 XX 相比提升 ZZ%"），技术细节要经得起教授追问（slide-skill 包）。
2. 8 部分顺序是硬约束：痛点 → 概述 → 核心技术 → 商业模式 → 应用/落地 → 社会价值，不许自创章节（青创北京 DOCX）。
3. 选题从真实问题来：大奖出自农业、制造业、信息技术服务、文化创意服务、社会服务五类，都是"从实际问题中来，到实际问题中去"（知乎经验帖）。
4. 痛点写法：三个并列的行业共性痛点 + 一个技术原理体系收束，关键指标只给一个（相变微显示新闻）。
5. 结尾不要拔高：社会价值 ≤1 页，写具体数字和落地证据，不要空话（青创北京页数上限 + 知乎细节教训）。

### 黑客松共性结论（只从上面 7 个"看到内容"的条目提炼；方法论来源另见 Devpost）

视觉共性：
1. 架构图是第一视觉：获奖答辩 PPT 的标题就是架构名（Adaptive Architecture、Less Than Nothing），三层解耦、黑板系统这类结构画成框图，线上标数据形态（Tsec 仓库）。
2. demo 代替 PPT 美化：Devpost 官方指南明文——"PowerPoints aren't forbidden but the best demos rely on showing off your project in action"；小红书巅峰赛全场大奖是现场弹吉他，不是放 PPT。
3. PPT 只有 6–8 页，demo 放第 3–4 页；在线提交页要有截图 + 视频 demo，评委先看在线材料再定决赛名单（Devpost 指南）。

逻辑共性：
1. 三段式：快速讲清问题（几句话）→ 现场 demo 正在跑的产品 → 一两句讲未来潜力（Devpost《How to present a successful hackathon demo》原文结构）。
2. 开场一个反常识主张或一个真实故事：Bytex"反对预定义角色分工"、For Future"零领域知识是主动排除"、脑控轮椅"丈夫两次脊椎损伤"——都不是"大家好我们做了个 App"。
3. 每层/每个机制配一个解决的问题：ai 小分队三层解耦的每一层都对应一个具体故障（上下文腐败、结束判定、并行竞争），不堆功能列表。
4. 数字只给硬数字：唯一 AK（54/54 题）、7692 元成本、90.7% 解题率、400 万患者——没有"用户量大、市场广"这类空话。
5. 结尾卖梦想，不总结功能：Devpost 原文——"spend a sentence or two highlighting its potential"，讲长期影响，不重复前面讲过的功能。

### （三）个人分享帖提炼（只从本节 29 个"看到内容"的条目提炼）

**视觉共性 5 条**
1. 极简商务风最稳：白底 + 一个高饱和主色（深蓝、墨绿或哑光橙）+ 浅灰辅助色；远离炫光粒子、立体小人、3D 星球——投影仪 + 大屏下太花会发灰、动画太复杂会卡顿（G3）。深色科技风只适合封面/章节/架构页，内容页一律浅色高对比（与 SKILL.md 合规克制版一致）。
2. 颜色 ≤3–4 种、字体 ≤2 种是硬上限：全篇总颜色不超过 3 种，不用红配绿、红配紫（G29）；字体选宋体、黑体等简洁易读字体，颜色控制在 3–4 种（G30）；字号 30 号左右，关键字加粗换颜色（G29）；数模答辩字体 ≥18px、标题 ≥24px（G1）。
3. 标题写成结论句，不写名词：不要写"市场分析"，改成"2000 万大学生闲置物品流转需求未被满足"（G3）；每页只传达一个核心观点（G3、G13、G23）。
4. 图表是默认语言：流程图、逻辑链图、时间轴、对比图、架构图代替大段文字；表格只留横线、去掉竖线；每页右下角加浅灰小页码，方便评委做笔记定位（G3）；表现力上字＜图片＜表格（G8）。
5. 封面三要素 + 封底复用：封面是项目名 + 一句话价值主张 + 汇报人/单位（G3、G21）；封底把项目名改成口号收尾，与封面呼应（抖音 D3 相关视频口播）。

**逻辑共性 5 条**
1. 黄金三秒开场：不要上来就讲大背景，从一个具体的、有代入感的故事或痛点开始（抖音 D12 相关口播）；先讲市场痛点和痒点，再给核心观点（一句话能说清），再讲解决方案，最后用真实数据支撑（G31）。
2. 骨架高度一致：七段/六点结构——背景/痛点→方案/产品→市场/竞品→商业模式→团队→财务/融资→规划（G3、G6、D2）；学术版换成背景—目的—方法—成果—结论与展望（G30）；数模答辩是问题—假设—模型—求解—结果—验证—敏感性—结论（G1）。
3. PPT 是提词器不是演讲稿：先写逐字稿、再拆每页关键词和图；每页只讲一个核心观点，PPT 里有的内容口头上可以不重复（G3、G13）；一页尽量不出现 2 个句子，只展示关键词，剩余部分口头讲（G6）。
4. 答辩固定结构：先给结论、再给一个证据、最后主动说边界；主动认一块短板反而说明真做过（G2）；预设五类问题：产品、市场、知识产权、团队、竞争与投资（G7）；问答用 ARG 框架：结论→理由→例证/数据，不会的问题不编造（G1）。
5. 页数按时间倒推：5 分钟≈7–11 页（G14、G23），5–8 分钟≈15–20 页（G3），15 分钟数模答辩有固定分钟分配（G1）；视频演示 ≤30–60 秒，放开头或原型页（G8、G13）；附录备用页（完整推导、数据表）不主动展示，评委追问时切过去（G1）。

**最值得借进 tech-style 的 5 个具体做法**
1. "标题即结论"规则 → 写进 `references/style-tokens.md` 与 `assets/pptx-template.md`：每页标题必须是完整结论句，禁止"市场分析""团队介绍"这类名词标题（来源：G3）。
2. 每页右下角浅灰小页码 + Section 标签 → `assets/pptx-template.md` 母版与 `assets/template.html` HUD：页码方便评委做笔记定位（来源：G3、G24）。
3. "路演安全版"第三预设（白底 + 单高饱和主色 + 浅灰辅助）→ `references/html-presets.md` 与 `assets/template.html`：与深色炫技版并列，投影仪/正式评审默认用它（来源：G3、G34）。
4. "按分钟倒推页数"表 → `references/competition-outlines.md`：5 分钟 7–11 页、5–8 分钟 15–20 页、15 分钟数模答辩分钟分配、每页秒数时间表（来源：G1、G3、G13、G14、G23）。
5. 答辩备用页 + ARG 问答结构 → `references/competition-outlines.md` 与 `references/export-routes.md` QA 清单：附录放完整推导/数据表/预设问答，不主动展示；答辩先结论、再证据、最后说边界（来源：G1、G2、G7）。

### （三）评审/投资人喜欢的风格——8 条硬结论（每条注明出处）

1. **第一页就要回答三个问题：你们是谁、解决什么问题、市场多大**（L1、L8、L25）。封面不要深蓝渐变 + 抽象几何图形——看完不知道公司干什么就是反面案例（L8）；改成白底黑字一行大字，如"用 AI 帮便利店减少 30% 生鲜损耗——覆盖 1200 家门店"（L8）。
2. **投资人平均扫 deck 不到 4 分钟，前 5 页决定 80% 印象；评委每页约 7 秒**（L8、L1、L13）。10–12 页是硬上限，超过 12 页丢注意力；异步阅读（手机 3 分钟内扫完）是前提（L1）。比赛版 12 页融资稿只留 6–7 页（G2）。
3. **白底黑字是投资人最不会错的选择；深色科技风只做封面/章节/架构页**（L8、L25、L24）。纯色或极简渐变背景、最多两种字体、图表扁平化不要 3D、每页一个视觉重心（L8）；浅色背景深色文字永远是安全的（L25）。深色科技风的可抄配方：Codia 深海军蓝 + 发光青色电路 + 玻璃质感（L27）、Wonderslide Nocturne 沉静午夜藏青 + 哑光卡片 + 冷调蓝紫高光（L20）、html-ppt-skill `tech-sharing` 深色 GitHub 风 `#0d1117` + JetBrains Mono + 终端代码块（L14）。
4. **每页一个观点，每页不超过 20 个词/30 个字，标题不超过 3 个字 + 一张图**（L1、L25、L8）。Airbnb 每页标题不超过 3 个字 + 一张图，4 秒可吸收（L1）；一页不要超过 20 个词，路演是"讲"的不是"读"的（L25）；平均每页 150–200 字太多（L8）。
5. **数据页的写法是固定的：左上角一句话"这一页想证明什么"，右下角"所以这意味着什么"**（L9）。图表用品牌色、重点数字放大、坐标轴灰色（L9）；数据用大数字 + 趋势图，不要贴表格（L25）；投资人要的是"这个趋势说明了什么"，洞察比数据本身更重要（L25）。
6. **竞争页只列 3 个真正重要的维度，并承认对手在某些地方做得不错**（L8、L1）。不要 12 维全勾表（L8）；用一张真实的地图标出切入点，像 LinkedIn 那样诚实（L1）；国赛版是 4–6 维对比表且本项目列高亮（L13）。
7. **结尾不要"谢谢"/"Q&A"，要写行动号召**（L8、L25、L9）。最后一页写融多少钱、干什么、联系方式/二维码（L8）；比赛版结尾是"我们下周可以做到的事"（KeyNote AI 提示词指南）；封底把项目名改成口号收尾，与封面呼应（见五、（三）第 5 条）。
8. **中国比赛评审版另有一套硬约束，与投资人版不完全相同**（L13、L23、G2）。按评分维度分页数——个人成长 30 分、项目创新 30 分、产业价值 25 分、团队协作 15 分（L13）；省科技奖权重是核心技术创新 30%、应用效益 30%、行业痛点与战略价值 20%、知识产权与行业带动 15%、团队与合规 5%（L23）；融资稿答"钱能不能赚回来"，评分表问"这件事该不该被支持"，两者不能混用（G2）。做比赛 PPT 先看评分表、再排页数；做融资 deck 先看投资人 10 页骨架（L1）。
