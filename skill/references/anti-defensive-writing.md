# 反防御性写作（Anti-Defensive Writing）

> **硬性规则：本 skill 生成的 PPT / HTML 里的全部文字，一律不得出现防御性写作。**
> 事实出处只说一次，不反复免责；判断直接下，不先自我设限再收回。
> 本文件是规则总汇，写每一页文字之前先读它；交稿前按第 6 节逐句自查。

> **仅限用户个人本地使用，不对外分发、分享或商用。**

## 2. 什么是防御性写作，为什么它毁掉一页 PPT

防御性写作（Defensive Writing）就是：作者还没等读者质疑，自己先道歉、先免责、
先把判断用层层限定词包起来。Kiterlin 的定义：前置道歉、重复免责声明、
层叠模态对冲词（或许/可能/潜在/在一定程度上）以及自我贬低式铺垫。

对 PPT / HTML 演示来说，它比在论文里更致命：

- **评委和投资人把它读成心虚。** Adkid 的原话：审稿人还没开口，自己先把
  "遗憾的是""效果有限""仍明显落后"写满了，等于提前把刀子递到对方手里，还附赠一份使用说明。
  路演只有 3–5 分钟，评委没时间替你把"可能在一定程度上"翻译回一句人话。
- **它吃掉每页唯一的一个观点。** 每页只能讲一个观点，防御句占了标题、段首、
  段尾三个最显眼的位置，真正的判断反而没地方站。
- **它稀释证据强度。** Kiterlin：这些写法稀释了实证发现的强度，遮蔽了核心创新贡献。
  同一个数字，写"准确率 89%，基线 90%"是事实；写"准确率相对较低，表明仍存在明显局限"
  是把一个合理权衡病理化成缺陷。
- **它是 AI 味最明显的标志之一。** 每段结尾升华、每页一个"总的来说"、每句一个
  "值得注意的是"，读者一眼就知道这是模板套出来的，不是人写的。

一句话原则（Adkid 原文，照搬）：
**论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。**
套到本 skill：**路演是一场发布会，不是项目总结。** 发布会只讲一件事：你最强的那个优势。

## 3. 四大原则（Kiterlin 原文，照搬并译成 deck 用法）

| 原则 | 原文操作准则 | 在 PPT / HTML 里怎么做 |
|---|---|---|
| **观点直接前置** | 段落与贡献陈述直接以实证发现和理论论点破题，坚决杜绝以局限性或退让性从句作为开头 | 每页标题就是判断本身，不是"关于……的初步探讨"；第一行写结论，第二行再给证据 |
| **正向界定范围** | 明确陈述本研究具体分析、测试与解释了什么，彻底摒弃习惯性的"我们并不声称……"否定句式 | 不写"我们并不声称覆盖所有场景"，写"本次覆盖 3 类场景：A、B、C"；范围用肯定句写出来 |
| **精准校准不确定性** | 严格区分必要的方法局限与怯懦的词汇堆叠（如"或许可能潜在提示"）；不确定性必须直接溯源至具体的研究设计边界 | 不确定的事只留一层限定，并且说清不确定来自哪里（样本量、时间、口径），不堆三四个"可能" |
| **篇章结构解耦** | 真实的方法局限归位至专门章节（方法、讨论或局限），避免在摘要、引言、贡献点与结论中反复稀释主线 | 真实的局限只写一次，放在"局限/风险"那一页（或备注里），不在封面、痛点页、结论页重复出现 |

## 4. 禁用词表（查到一处，改掉一处；删不掉的按"直接替换"改）

### 4.1 套话与总结腔：直接删，删完不补

| 禁用 | 为什么禁 | 直接替换 |
|---|---|---|
| 需要注意的是 / 值得注意的是 / 需要指出的是 / 不可否认的是 | 段首零主语评论，删掉不影响任何信息 | 直接删，后面那句话原样留下 |
| 总的来说 / 总而言之 / 综上所述 / 综合来看 / 总体而言 / 简而言之 / 一句话总结 | 每段结尾升华、结构预告，是 AI 味的头号标志 | 直接删，让段落自然收束；结论页只写结论本身 |
| 这轮消息真正值得记住的是什么 / 真正让人停下来的一句 / 合起来说明了一件事 | 替读者总结、替读者感动，AI 短剧味 | 删整句 |
| 首先 / 其次 / 此外 / 最后（作结构填充时） | 结构化废话，骨架先于内容 | 删，靠版式（序号、卡片）分节，不靠连接词 |
| 在当今时代 / 随着科技的发展 / 在……的背景下 | 空泛开场，任何稿子都能套用 | 删，直接写事实 |
| 不难发现 / 显而易见 / 众所周知 / 毋庸置疑 | 假装共识，实际没有信息 | 删，改成数据或来源 |
| 深度赋能 / 助力……高质量发展 / 为……提供有力支撑 | 机械拔高、段末升华 | 删，换成具体做了什么、数字是多少 |

### 4.2 对冲与自我削弱：只留一层，写准来源

| 禁用 | 为什么禁 | 直接替换 |
|---|---|---|
| 或许 / 可能 / 潜在 / 在一定程度上 / 某种程度上（两两叠加时，如"或许可能潜在提示"） | 层叠对冲，三个词叠在一起等于没说 | 删到只剩一层，或直接改成证据句："证据表明，在所观测的条件下 X 对 Y 产生显著影响" |
| 遗憾的是 / 效果有限 / 仍明显落后 / 存在严重不足 / 仅 / 只能提供非常有限的参考 | 自我削弱式表达，主动示弱 | 删，换成事实："本文在两个标准基准数据集上系统评估了该方法的性能表现"；不占优的指标写成权衡，不写成缺陷 |
| 本文弱于 / 性能下降 / 未能超过 / 准确率相对较低，表明仍存在明显局限 | 把一个指标落后写成整个方法有问题 | 写成权衡："该方法将延迟从 100 ms 降至 60 ms，准确率为 89%，基线为 90%" |
| 仅仅做了初步尝试 / 仍有很大提升空间 / 只是……而已 | 习惯性谦辞、自轻表达 | 删，写做了什么："本文在两个数据集上评估该方法" |
| 尚未经过独立验证（反复出现时） | 免责式表述，事实出处只说一次 | 只在相关主张旁边写一次，不在每页重复 |
| 属于……、不等于…… / 出自……、属于对未来的判断，不是已经验证的时间表 | 定义式、免责式表述 | 删，事实出处只标清一次，判断融进正文 |

### 4.3 翻案句与虚设反方：拿掉虚设的 X，Y 若还是抽象判断整句删

| 禁用 | 为什么禁 | 直接替换 |
|---|---|---|
| 不是 A，而是 B / 不仅是……更是…… / 与其说……不如说…… / 看似……实则…… / 你以为……其实…… | 虚设一个没人说过的 A 再否定它，翻案句本身就是 AI 味 | 拿掉 A，只写 B；B 若还是抽象判断（"不仅是考验，更是契机"），整句删，不换壳 |
| 当然……但是…… / 虽然……但是……（作习惯性让步时） | 先退一步再说正事，判断被让步句稀释 | 删让步从句，直接写判断；真有限制时写成正向范围（见第 3 节） |
| 需要澄清的是 / 这并不是说…… / 这不应被理解为…… / 我们并不声称…… / 我们并不试图…… / 目标不是 X，而是 Y | 否定句式界定范围，读者先记住你"不是什么" | 改成肯定句："本文分析了 2015 至 2023 年的城市治理案例" |
| 未来值得关注的，主要有三方面（提纲式收尾） | 提纲式清单收尾，判断没融进正文 | 删清单，判断融进正文各段 |

### 4.4 其他：冒号逻辑与空承诺

| 禁用 | 为什么禁 | 直接替换 |
|---|---|---|
| 冒号逻辑：先抛一句再用冒号引出解释（"技术一侧不用展开太多，一句话就够了：……"） | 用户 2026-11-04 定死的硬规则：正文任何表述都不要用冒号和冒号逻辑的话语 | 技术直接一句话讲完，不加交代句 |
| 建议持续关注 / 我们要关注 / 要完善 / 要进一步 / 应结合实际情况 / 不断优化完善 | 空承诺、万能正确话，删掉后读者什么都没少知道 | 删，换成具体做了什么或具体没做什么 |
| 研究表明 / 专家认为（无来源时） | 模糊归因 | 有来源就写来源，没有就改成作者自己的判断并写明范围，不只删"研究表明"让论断变裸事实 |
| 显著提升 / 值得推广 / 具有重要价值（无数据时） | 没有依据的评价 | 有数据就改成数据，没有就删，不编数字 |

### 4.5 守住的底线：这些不是防御性写作，不删

- **必要的限定，写一次、写准、放在相关主张旁边。** 会影响判断成立、证据理解、
  适用范围、研究设计、读者正确使用的限制，必须保留。删的标准是 Devilyuu 的
  一句话检验："这句删掉后，读者少知道了什么？"少知道了事实、范围、立场、后果或
  下一步，就只能写准，不能删；什么都没少，就是防御填充。
- **真实的犹豫、未完成、局限，原样保留。** "延迟和错误率还没测出来，先继续观察"
  "其中的原因我们还不完全清楚"这类真实的不确定不删；删的是无依据的自我削弱，
  不是作者真实的不确定。真实的局限只写一次，放在"局限/风险"页或备注里。
- **事实与承诺 > 一切。** 不为显得强势编造数据、基线、结果、机制、因果。
  观测到的关联不写成因果；没有数据的好话不写，删掉，不编数字顶上。
- **来源标记只标一次。** "据报道""报道显示""报道称""公开记录显示"轮换使用，
  同一事实不在每页重复标出处。

## 5. 改写前后对照（deck 专用，例子只说明写法，事实不能搬进别的任务）

### 5.1 标题页

- ❌ "关于外贸获客流水线的一个初步探索"（"初步"自轻，标题先退一步）
- ✅ "外贸全自动获客流水线"（标题就是判断本身）

### 5.2 痛点页

- ❌ "值得注意的是，传统获客方式在一定程度上可能存在效率方面的局限性。"
  （"值得注意的是"套话 + "在一定程度上""可能"层叠对冲 + "效率方面的局限性"抽象大词）
- ✅ "人工找客户，一天只能发 20 封开发信。"（事实一句，数字一个）

### 5.3 方案页

- ❌ "我们并不声称这套流水线适用于所有行业，而是针对外贸场景做了优化。"
  （否定句式界定范围）
- ✅ "这套流水线覆盖外贸获客 5 步：爬取、筛选、写信、转 PDF、发送。"（正向界定范围）

### 5.4 数字页

- ❌ "总的来说，准确率相对较低（89% 对比基线的 90%），表明本方法仍存在明显局限。"
  （总结腔 + 一个指标落后写成整个方法有问题）
- ✅ "延迟从 100 ms 降到 60 ms，准确率 89%，基线 90%。"（权衡就是权衡，数字自己说话）

### 5.5 结论页

- ❌ "综上所述，未来值得关注的，主要有三方面：第一，持续优化；第二，不断完善；第三，结合实际情况推进。"
  （总结腔 + 提纲式收尾 + 三个空承诺）
- ✅ "下一步先跑 20 家客户，验证送达率。"（一句行动，写清做什么）

### 5.6 论文 / 学术场景（Kiterlin 对比矩阵原文，照搬）

- ❌ "虽然解决平台治理的长期争端显然超出了本项初步探索的范围，但或许可以谨慎地指出……"
- ✅ "算法内容治理显著重塑了在线社区的用户参与生态。"
- ❌ "这些实验结果在某种程度上或许可能潜在提示 X 对 Y 具有一定影响。"
- ✅ "实验证据表明，在所观测的条件下 X 对 Y 产生显著影响。"
- ❌ "本文仅在两个数据集上做了初步尝试，所获结论只能提供非常有限的参考。"
- ✅ "本文在两个标准基准数据集上系统评估了该方法的性能表现。"

### 5.7 路演叙事（Adkid 规则套到 deck）

- 路演不是工作汇报，不按"我们先做了什么、后来尝试了什么、哪些失败了"展开；
  只保留最终成立的逻辑：问题为什么重要 → 现有方法为什么不够 → 我们提供了什么新解法 → 证据如何支持。
- 打不赢的指标不设为比赛：某指标不占优势，就不要把叙事建立在该指标上，
  重新选更能反映价值的任务定义、评价维度、应用场景或比较口径。
- 优势必须被明确说出来，不要期待评委自己从表格中发现贡献：
  在哪个条件下表现最好、为什么会出现这种优势、解决了什么实际问题、为什么值得关注。

## 6. 交稿前自查清单（逐句读全文，一处不漏）

1. **先读一遍，删套话。** 全文搜第 4.1 节的词：需要注意的是、值得注意的是、
   总的来说、综上所述、首先/其次/此外，查到一处删一处；删完发现原文也没什么
   真东西，问题在内容本身，不在词。
2. **再读一遍，拆对冲。** 搜"可能""或许""潜在""在一定程度上"，两两叠加的
   全拆；只留一层，并且问一句：不确定来自哪里？答不上来就删。
3. **翻案句检查。** 搜"不是……而是……""不仅是……更是……"，拿掉虚设的 X；
   剩下的 Y 若还是抽象判断，整句删，不换壳（不改成"A 固然……但 B"）。
4. **每段第一句检查。** 段落开头是不是局限、让步、道歉？是就重写：第一句必须是
   观点、事实或数字。
5. **结尾检查。** 结论页有没有突然冒出来的自我否定、新的局限、提纲式清单？
   有就删；结论只强化记忆点：解决了什么、提出了什么、证明了什么、为什么重要。
6. **重复免责检查。** 同一个出处、同一个局限在全文出现了几次？超过一次的，
   只留一次，放在相关主张旁边。
7. **事实对账。** 数字、日期、来源、比较基准、责任主体、完成状态逐条核对原文；
   没有依据的好话（"显著提升""值得推广"）有数据改成数据，没有就删，不编数字。
8. **冒号检查。** 正文里还有没有"先抛一句再用冒号引出解释"的句子？有就改成
   直接的一句话。
9. **Adkid 六问（交稿前最后问自己）：** 这句话是否无意中扩大了要承担的责任？
   是否提出了一个本来没人要求回答的问题？是否把局部现象说成了普遍缺陷？
   是否用了比证据更宽泛的负面判断？有没有按"我们做了什么过程"在展开？
   有没有把不领先的指标设成了主战场？

## 7. 五阶段重写管线（Kiterlin 原文，照搬）

1. **功能诊断：** 识别句子属性——非必要免责 / 必要范围界定 / 方法学真实局限。
2. **剔除修剪：** 坚决删除无法增加证据、逻辑与认知价值的前置铺垫与道歉。
3. **正向投射：** 将"非 X 否定句"重塑为清晰的"专注 Y 正向主张"。
4. **不确定性校准：** 剥离层叠对冲（或许/可能/潜在），将疑问锚定至具体设计边界。
5. **结构对齐：** 以强主题句重筑段落主线，真实限制归入专门章节统一呈现。
